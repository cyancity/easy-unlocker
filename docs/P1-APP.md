# P1 手机 App 需求

> 产品切法：平行小库，只存用户允许 Agent 访问的条目。不平替 Bitwarden，不做自动填充。
> 现状：P1 App（指纹解锁 + 手选批准 + 借用一次性公钥密封回传）已在真机验收。本文件是 App 的需求真源。
> 实现：`android/`（Android Studio 打开）；协议：`seal_public_key` + `POST /v1/device/pair` + `GET /v1/device/pending` + 批准时带 `v2` box。推送只有 FCM 一条路。

## 1. 产品边界

| 做 | 不做 |
|---|---|
| Agent 白名单凭据（API key 等） | 用户全部生活密码 |
| 通知上批准 / 拒绝 | 浏览器或系统 autofill |
| 本地查看、添加、删除 | 接 Bitwarden API 同步 |
| 一次一条导入（粘贴），或从 Bitwarden 未加密 JSON 里勾选导入 | 整库一把梭导入 |
| 密封备份文件（可拷走） | 第一版做 Dropbox / Drive / iCloud 客户端 |
| Android 先 | 第一版 iOS |
| | 第一版 SSH 短时证书（另一类对象，P1.1） |

生活密码继续用 Bitwarden。Agent 要用的条目，人手贴进本 App 一次，或从 BW 导出里勾选几条导进来。

## 2. 密码学与传输

### 2.1 静止层（库）

- 条目默认只存在本机，加密存放。
- 学 BW/1P 的形状：主密钥派生（Argon2 一类）→ AES-GCM 封条目；指纹/面容只是把已有库密钥从系统密钥库拆开，**不是**把指纹发给服务器。
- 指纹不能当唯一密钥。

### 2.2 密封备份（原「恢复码」和「密文备份」是同一件事）

- 初次设置写出一份 **恢复材料**（本地 txt；以后可丢进网盘）。日常解锁用系统指纹/面容，不手打恢复码。
- 随时可导出一份 **密文备份文件**；没有恢复材料解不开。
- 换机、丢手机：导入该文件 + 恢复材料。生物识别是本机便利，不能用来恢复新设备。
- 以后网盘同步 = 把这份密文文件放进 Dropbox / Drive / iCloud，不另做一套同步协议。第一版只保证文件格式能这样用。

### 2.3 传输层（双层里的第二层）

- 每次 `easyGet` **现场**生成临时密钥对，私钥只在这次进程内存，用完清除。禁止安装期长期 CLI 私钥。
- 请求把临时公钥绑在 `request_id` 上推到手机，不能事后另送一把公钥（防 Broker 掉包）。
- 用户在手机本地解锁并取出这一条后，立刻用该公钥密封；Broker **只转发密文，不能解密**。
- CLI 用内存私钥解开，写入 `--write-to`，明文和私钥出内存。
- 现有 `internal/securepayload`（pairing token 派生）是 M1 脚手架：Broker 也能解。P1 必须换成本节。

## 3. 两种解锁

| | Agent 请求 | 用户自己打开 App |
|---|---|---|
| 触发 | 通知 / 待批准 | 点开 App 浏览、添加、删除 |
| 解锁 | **每次请求都要**生物识别（或等价本机认证），一次性 | 会话随 **App 进入后台/退出即锁上** |
| 解密范围 | 只解开用户点选的那一条 | 浏览所需的元数据；查看某条明文时再拆那一条 |
| 不能 | 不能因为「刚才在库里逛过」就免掉批准指纹 | 不能把浏览会话拉长成 BW 那种长时间整库解锁 |

批准路径与浏览路径分开计时、分开授权。打开过库 ≠ 自动批准下一条 Agent 请求。

**授权边界（2026-09-14 定稿）**：解锁一次之后，浏览库（进条目、看明文、复制）**不再逐次要求指纹**，直到 App 退到后台自动上锁；需要指纹的只有**创建库、解锁、以及每一次放出决策（批准 / 拒绝后确认）**。截屏由全 App 的 `FLAG_SECURE` 挡住，不靠逐次授权兜底。

## 4. 条目对不上（`OPENAI_API_KEY` vs `my-api-key`）

CLI 里的 `item` 只是 **请求名 / 提示**，不是全球唯一 ID。人对得上才放行。

1. 手机批准页展示：谁、要什么（请求名）、为什么、用多久。
2. 下面是本库条目列表。若某条的 **名称或别名** 与请求名完全一致，则预选；否则不预选，用户必须手点。
3. 用户可改选其它条目，或当场添加/导入再批。
4. 批准时可勾选「以后把这个请求名记成该条目的别名」。下次 `easyGet env OPENAI_API_KEY` 就能预选到 `my-api-key`。
5. 放出哪一栏：默认**非空的那栏**（密码有值发密码，否则发备注）；两栏都有时批准页可以手切「密码 / 备注」。所选栏为空则不放行。
6. **放出方式**（请求里的 `delivery`）必须让用户看见后果：
   - `file`（默认）：黄标「会写入 `<target>`，内容留在那台机器上，直到你手动删掉」，按钮「确认写入磁盘」。
   - `ephemeral`：中性标「不落盘，用完即焚」，按钮「放出（不落盘）」。
   - 老 CLI 不带这个字段时按 `file` 显示（向后兼容）。
7. **禁止**按相似度自动匹配（避免批错 key）。

删除条目时别名一起删。重名：同一名称或别名在库内必须唯一。

## 5. 库内功能

- 一条条目有**两栏**：密码（短值：token）与备注（长文本：SSH 私钥、整段 `.env`、说明）。两栏都可空，但至少一栏非空。
- 添加、查看、删除、编辑（名称、密码、备注）。轮换 = 改值或删旧贴新。
- 导入：
  - 一次一条（粘贴）；
  - 或「设置 → 导入 Bitwarden 导出」选 BW 的未加密 `.json`，**逐条勾选**要的条目再导入（搜索框按名称/用户名过滤）。
  - 映射：BW `item.name` → 条目名，`login.username` → 别名，`login.password` → 密码，`notes` → 备注。
    认 `type == 1`（登录）与 `type == 2`（安全笔记，只有 notes；SSH 私钥、OCI config 常是这种）；
    `login.totp` / 自定义字段 / `uris` / 其它类型仍不读。名称或别名冲突的整条跳过，别名冲突只丢该别名；
    同一用户名落在多条候选上时语义不唯一，整批都不记该别名（不许按文件顺序替人预选）。
  - 重导补备注：命中**同名**且库里该条备注为空时，只把导入项的备注补上，不动密码、别名等其它字段，也不新建条目。老版本导入只收密码栏，靠这条不用删条目重导就能补回 notes。
  - `encrypted: true` 的导出直接拒绝并提示改导未加密。
  - 导入的明文密码/备注只经内存，不落盘、不进日志；勾选页只拿名称和用户名。
- 名称校验：只要求非空 + 库内唯一（不再限制字符集，BW 里带空格/中文的名字能原样导入且可继续编辑）。
- 查看明文时挡住系统截屏（全 App `FLAG_SECURE`）；复制限时清剪贴板。条目详情是**单页两栏**：密码、备注上下排开、各自带「复制」，空的一栏显示 `--`，不来回切换。
- 条目列表要**保持滚动位置**：进详情/编辑再返回，不能跳回第一条。
- 系统推送文案不写条目名和路径；详情进 App 再看。

## 6. 网关（配对）与请求

- App 与 Broker 配对（现有 pairing 思路：设备只拥有「发起/接收批准」，读不到库）。
- **一台手机可以同时配多台网关，随时切换，互不覆盖**：设置 → 网关 → 列表里「切换」。
  网关只决定「往哪儿发待批准 / 决定」；**切换不动本地条目**（`vault.eu1` 与网关完全解耦）。
  同一 URL 再次配对 = 更新那台的设备令牌（轮换 token），不会多出一条。
- 每个网关一套设备令牌；FCM 令牌是设备级的，添加/启动时给**所有**网关注册一遍，谁都能推你。
- 切换网关会清掉旧网关的待批准列表（那些 request 属于它），然后立刻拉新网关的。
- 推送载荷带 `gateway`（网关公网地址）：点通知先切到对应网关再进待批准。
  旧 Broker 不带这个字段时行为不变（App 向后兼容，所以 App 可以先发）。
- 超时 fail closed，与现协议一致。
- 伪造/重放 decision 仍须拒绝。

## 7. P1 验收（作者自己）

1. 装 App，抄下恢复材料，导出密文备份后能在「清数据」后恢复库。
2. 贴入一条 Agent 用的 key（名称与 `easyGet` 不一致也行）。
3. `easyGet env <请求名> --write-to ... --for "..."` → 通知 → 指纹 → 手选条目（可加别名）→ 文件里有值。
4. `easyGet` 的 stdout、Broker 日志、推送文案里都没有明文。
5. App 切到后台后再进，浏览库需要重新认证；这期间来的 Agent 请求仍要再按一次指纹。**解锁后到切后台之间**，进条目看明文/复制不再弹指纹。
6. 没有设备令牌（未配对）不能取出任何条目。
7. 一条只有备注的条目（SSH 私钥）能被请求放出，批准页显示「放出：备注」，落盘内容与备注逐字一致。
8. 旧的库文件用新版本打开：条目不丢、能解锁，备注为空。
